# Install and configure open metadata



## 1. Download the distribution

You can get the latest release from the GitHub repo: https://github.com/open-metadata/OpenMetadata/releases/latest

At the time(19/08/25), the latest release is 1.9.x. So we run the below command to get the tar ball

```shell
wget https://github.com/open-metadata/OpenMetadata/releases/download/1.9.0-release/openmetadata-1.9.0.tar.gz

mkdir -p /opt/openmeta
mv openmetadata-1.9.0.tar.gz /opt/openmeta/

# untar it
tar -xzvf openmetadata-1.4.0.tar.gz

cd openmetadata-1.9.0

```

> All the **OM conf files** is located at the `conf` folder

## 2. Configure the openmeta app

The main configuration file of OM is found under `path/to/openmetadata/conf/openmetadata.yaml` 

You can also notice that, the yaml file is a template which takes the env var value first, if not defined, it takes
a `default value in the template`. 

> I recommend you to replace the default value in the template by your prod deployment value. If you want to overload
> these values, just use the export env var.
> 

The **openmetadata-env.sh** can host all your custom configuration values by using the pattern `export key=value`

The `DB` and `EL` are the minimum required components for running `OM`.
As a result, the minimum config is to set up the target `DB` and `EL`.

> We recommend you to use **export key=value** paradigm inside `openmetadata-env.sh`
> 
### 2.1 DB config

The db config in the `openmetadata.yaml` is shown 

```yaml
database:
  # the name of the JDBC driver, mysql in our case
  driverClass: ${DB_DRIVER_CLASS:-com.mysql.cj.jdbc.Driver}
  # the username and password
  user: ${DB_USER:-openmetadata_user}
  password: ${DB_USER_PASSWORD:-openmetadata_password}
  # the JDBC URL; the database is called openmetadata_db
  url: jdbc:${DB_SCHEME:-mysql}://${DB_HOST:-localhost}:${DB_PORT:-3306}/${OM_DATABASE:-openmetadata_db}?${DB_PARAMS:-allowPublicKeyRetrieval=true&useSSL=false&serverTimezone=UTC}
  maxSize: ${DB_CONNECTION_POOL_MAX_SIZE:-50}
  minSize: ${DB_CONNECTION_POOL_MIN_SIZE:-10}
  initialSize: ${DB_CONNECTION_POOL_INITIAL_SIZE:-10}
  checkConnectionWhileIdle: ${DB_CONNECTION_CHECK_CONNECTION_WHILE_IDLE:-true}
  checkConnectionOnBorrow: ${DB_CONNECTION_CHECK_CONNECTION_ON_BORROW:-true}
  evictionInterval: ${DB_CONNECTION_EVICTION_INTERVAL:-5 minutes}
  minIdleTime: ${DB_CONNECTION_MIN_IDLE_TIME:-1 minute}

```
This template uses the syntax `${ENV_VAR:-default}`:
- If the environment variable VAR exists, it takes the `ENV_VAR value` first
- If `ENV_VAR` not set, it takes the value `default`. 

For example, `driverClass: ${DB_DRIVER_CLASS:-com.mysql.cj.jdbc.Driver}`, if no env var `DB_DRIVER_CLASS` is defined,
the value `com.mysql.cj.jdbc.Driver` will be used as the value of `driverClass`. If I defined `export DB_DRIVER_CLASS=org.postgresql.Driver`
then the `driverClass` value will be `org.postgresql.Driver`

#### 2.1.1 For connecting to a postgres

Below are the minimum env vars you need to define to use a postgresql server

```shell
export DB_DRIVER_CLASS="org.postgresql.Driver"
export DB_SCHEME="postgresql"
# this line config the jdbc connection parameters that disable SSL, allow key retrieval, and set the timezone.
# this parameters are valid for mysql not for postgres. postgres will just ignore them
export DB_PARAMS="allowPublicKeyRetrieval=true&useSSL=true&serverTimezone=UTC"
export DB_USER="openmetadata_user"
export DB_USER_PASSWORD="changeMe"
export DB_HOST="localhost"
export DB_PORT="5432"
export OM_DATABASE="openmetadata_db"
```

#### 2.1.2 For connecting a mysql

```shell
export DB_DRIVER_CLASS='com.mysql.cj.jdbc.Driver'
export DB_SCHEME='mysql'
# this line is essential for mysql server connexion
# if not compatible with mysql server config, the communication will never be done
export DB_PARAMS='allowPublicKeyRetrieval=true&useSSL=true&serverTimezone=UTC'
export DB_USER='openmeta'
export DB_USER_PASSWORD='changeMe'
export DB_HOST="localhost"
export DB_PORT="5432"
export OM_DATABASE="openmetadata_db"
```

By default, OpenMetadata comes with a Basic authentication(Username & Password) Mechanism. OM supports many other 
authentication(e.g. ldap, keycloak, etc.). The default Username and Password for Login are:

```text
Username - admin@open-metadata.org
Password - admin
```

When using a custom domain, configure the principal domain as follows:
```yaml
config:
    authorizer:
      adminPrincipals: [admin]
      principalDomain: "casd.local"

```
You need to do the below steps in your production env:
- **DELETE the admin default account** shipped by OM.
- **UPDATE the Private / Public keys** used for the JWT Tokens in case it is enabled.

#### 2.4.1 Authentication config

Below lines show the authentication config of the ``. As we will only show the setup of `basic` authentication provider.
The config details of other authentication provider(e.g. ldap, keycloak, etc.) are omitted.
```yaml
authenticationConfiguration:
  # Defines the type of OAuth client:
  # public → no client secret (used for SPAs, CLI, mobile).
  # confidential → requires client secret (server-to-server apps).
  clientType: ${AUTHENTICATION_CLIENT_TYPE:-public}
  # provider (basic by default)
  # Which authentication provider to use:
  # basic → username/password stored in OpenMetadata.
  # other providers google, okta, auth0, azure, customOidc, etc.
  provider: ${AUTHENTICATION_PROVIDER:-basic}
  # This is used by auth provider provide response as either id_token or code
  # id_token → common in implicit flow (token contains user identity claims).
  # code → authorization code flow, more secure, exchanges code for token.
  responseType: ${AUTHENTICATION_RESPONSE_TYPE:-id_token}
  # This will only be valid when the provider type specified is customOidc
  # Example: "keycloak", "mycompany-oidc".
  providerName: ${CUSTOM_OIDC_AUTHENTICATION_PROVIDER_NAME:-""}
  # JWKS (JSON Web Key Set) endpoints used to validate JWTs.
  # Default points to OpenMetadata’s own JWKS URL:
  publicKeyUrls: ${AUTHENTICATION_PUBLIC_KEYS:-[http://localhost:8585/api/v1/system/config/jwks]}
  # Algorithm used to validate JWT signatures. Common: RS256 (RSA + SHA-256).
  tokenValidationAlgorithm: ${AUTHENTICATION_TOKEN_VALIDATION_ALGORITHM:-"RS256"}
  # The base URL of the identity provider (used for discovery of endpoints).
  authority: ${AUTHENTICATION_AUTHORITY:-https://accounts.google.com}
  # The application’s registered client ID with the IdP.
  # Needed for OAuth/OIDC flows. Default empty.
  clientId: ${AUTHENTICATION_CLIENT_ID:-""}
  # The redirect URI where the IdP sends the user after login.
  # Example: http://localhost:8585/callback.
  callbackUrl: ${AUTHENTICATION_CALLBACK_URL:-""}
  # List of JWT claim fields OpenMetadata will use to identify the user.
  # Defaults: [email, preferred_username, sub].
  jwtPrincipalClaims: ${AUTHENTICATION_JWT_PRINCIPAL_CLAIMS:-[email,preferred_username,sub]}
  # Maps custom JWT claims to OpenMetadata user attributes.
  # [{"claim": "groups", "attribute": "roles"}].
  jwtPrincipalClaimsMapping: ${AUTHENTICATION_JWT_PRINCIPAL_CLAIMS_MAPPING:-[]}
  # enableSelfSignup (true by default)
  enableSelfSignup : ${AUTHENTICATION_ENABLE_SELF_SIGNUP:-true}
```

For the basic authentication provider, you need to set the minimum configuration:
- provider: basic (use in app db to store username and password)
- enableSelfSignup: true(This flag indicates that users can come and signup by themselves on the OM)

below lines are set up for `openmetadata-env.sh`.

```shell
export AUTHENTICATION_PROVIDER="basic"
# This flag indicates if users can come and signup by themselves on the OM
export AUTHENTICATION_ENABLE_SELF_SIGNUP="true"
```

#### 2.4.2 Authorizer config

```yaml
# Authorizer Configuration
authorizerConfiguration:
  # Use built-in OpenMetadata role/permission model as main authorization engine.
  # Advanced users can implement a custom authorizer by replacing this class.
  className: ${AUTHORIZER_CLASS_NAME:-org.openmetadata.service.security.DefaultAuthorizer}
  # This is the filter applied to each incoming request.
  # JwtFilter validates JWT tokens before passing requests into the system.
  # With basic auth, this still applies (session tokens are JWT-based internally).
  containerRequestFilter: ${AUTHORIZER_REQUEST_FILTER:-org.openmetadata.service.security.JwtFilter}
  # List of users who are global admins regardless of other settings.
  adminPrincipals: ${AUTHORIZER_ADMIN_PRINCIPALS:-[admin]}
  # defins who can register account 
  # ["all"] → any email is allowed.
  # ["company.com", "org.org"] → only users with those domains can self-register.
  allowedEmailRegistrationDomains: ${AUTHORIZER_ALLOWED_REGISTRATION_DOMAIN:-["casd.local"]}
  # Domain automatically appended to usernames when creating principals.
  # Example: if a user signs up as bob, OpenMetadata may treat them as bob@open-metadata.org.
  principalDomain: ${AUTHORIZER_PRINCIPAL_DOMAIN:-"casd.local"}
  # List of domains allowed for validated principals.
  allowedDomains: ${AUTHORIZER_ALLOWED_DOMAINS:-[]}
  # If true, all user principals must match principalDomain or entries in allowedDomains.
  # Used to prevent login from unauthorized domains when integrating with OIDC providers.
  enforcePrincipalDomain: ${AUTHORIZER_ENFORCE_PRINCIPAL_DOMAIN:-false}
  # If true, requires secure socket connection (mutual TLS) for authorization flow.
  # Usually left false unless you have a strict security environment.
  enableSecureSocketConnection : ${AUTHORIZER_ENABLE_SECURE_SOCKET:-false}
  # If true, OpenMetadata will import roles/claims from the authentication provider (e.g., Okta, Keycloak groups).
  # If false, roles are managed only within OpenMetadata.
  useRolesFromProvider: ${AUTHORIZER_USE_ROLES_FROM_PROVIDER:-false}
```
For the basic authentication provider, you need to set the minimum configuration:
```yaml
authorizerConfiguration:
  className: org.openmetadata.service.security.DefaultAuthorizer
  containerRequestFilter: org.openmetadata.service.security.JwtFilter
  adminPrincipals: [admin]
  allowedEmailRegistrationDomains: ["all"]
  principalDomain: "casd.local"
  allowedDomains: []
  enforcePrincipalDomain: false
  enableSecureSocketConnection: false
  useRolesFromProvider: false
```
below lines are set up for `openmetadata-env.sh`.

```shell
export AUTHORIZER_ALLOWED_REGISTRATION_DOMAIN='["mycompany.com","subsidiary.org"]'
export AUTHORIZER_PRINCIPAL_DOMAIN="casd.local"
export AUTHORIZER_ENFORCE_PRINCIPAL_DOMAIN="false"
export AUTHORIZER_ENABLE_SECURE_SOCKET="false"
export AUTHORIZER_USE_ROLES_FROM_PROVIDER="false"
```

#### 2.4.3  Enable JWT tokens

Once a user logs in with username/password, the service issues a JWT token for that session. 
That token is signed with the `private key (rsaprivateKeyFilePath)` and validated on every request with the
`public key (rsapublicKeyFilePath)`.

OM comes with a default private/public key pair and configuration, for test purpose, you can use them.

```yaml
jwtTokenConfiguration:
  rsapublicKeyFilePath: ${RSA_PUBLIC_KEY_FILE_PATH:-"/opt/openmetadata/conf/public_key.der"}
  rsaprivateKeyFilePath: ${RSA_PRIVATE_KEY_FILE_PATH:-"/opt/openmetadata/conf/private_key.der"}
  jwtissuer: ${JWT_ISSUER:-"open-metadata.org"}
  keyId: ${JWT_KEY_ID:-"Gb389a-9f76-gdjs-a92j-0242bk94356"}
```

For **production deployment**, it is a MUST to `update the JWT configuration`. 

To create private/public key use the following commands can be used:

```shell
# generate a rsa private key
openssl genrsa -out private_key.pem 2048
# convert private key to .der
openssl pkcs8 -topk8 -inform PEM -outform DER -in private_key.pem -out private_key.der -nocrypt
# gen public key in .der
openssl rsa -in private_key.pem -pubout -outform DER -out public_key.der
```

> Copy the `private_key.der` and `public_key.der` in OpenMetadata server conf directory. 
> Make sure the permissions can only be readable by the user who is starting OpenMetadata server.

Below are the modification you need in `openmetadata.yaml`

```yaml
jwtTokenConfiguration:
  rsapublicKeyFilePath: "/opt/openmetadata/conf/public_key.der"
  rsaprivateKeyFilePath: "/opt/openmetadata/conf/private_key.der"
  # Identifier for who issued the token.
  # Clients and services may check this value to ensure tokens come from the right source.
  jwtissuer: "casd.local"
  # A unique identifier for the signing key. Useful if you rotate keys (so multiple public keys can exist in JWKS).
  keyId: "casd-self-gen-2025-09-02"

```

below lines are set up for `openmetadata-env.sh` to avoid editing `openmetadata.yaml` directly.

```shell
export JWT_ISSUER="casd.local"
export JWT_KEY_ID="casd-self-gen-2025-09-02"
```

## 3. Init the databases and indexes

The command below will generate all the necessary tables and indexes in ElasticSearch.

```shell
./bootstrap/openmetadata-ops.sh drop-create
```
> Before running this command, make sure you have the required config setup in the `openmetadata.yaml`(e.g. login, pwd for elastic and postgresql/mysql).
> Otherwise, you will receive many error messages.

## 4. Start/stop the openmetadata service

After the `database tables` and `elasticsearch index` are created, you can now run the `openmetadata service`.

```shell
# start the om service
./bin/openmetadata.sh start

# the above command will start the om web server at port 8585
curl http://localhost:8585 
# and the web service at port 8586
curl http://localhost:8586

# get the status of om service
./bin/openmetadata.sh status
# expected output
OpenMetadata running with PID=142200.


# stop the om service
./bin/openmetadata.sh stop
```

> We recommend configuring serviced to monitor the OpenMetadata command to restart in case of any failures.
> 


### 4.1 Create systemd unit file for OM

Below is an example of systemd unit file for OM. For more details of systemd, you can visit this [page](https://github.com/pengfei99/LinuxAdminSys/blob/main/docs/debian_server/core/Systemd(serviced).md)

```shell
[Unit]
Description=OpenMetadata Service
After=network.target
Wants=network.target
Requires=postgresql.service elasticsearch.service

[Service]
Type=forking
# Run as non-root user
User=openmeta
Group=openmeta
WorkingDirectory=/opt/

# load env var
EnvironmentFile=-/opt/openmetadata/conf/openmetadata-env.sh

# How to start and stop
ExecStart=/opt/openmetadata/openmetadata.sh start
ExecStop=/opt/openmetadata/openmetadata.sh stop

# checking service health.
ExecReload=/opt/openmetadata/openmetadata.sh status
# Optional: status and clean hooks
ExecStartPre=/opt/openmetadata/openmetadata.sh clean

# Restart policy if the service crashes
Restart=on-failure
RestartSec=5

# Logging: send stdout/stderr to systemd journal
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target

```


## 6. Java Memory Heap Issue

If your openmetadata application logs speak about the below issue -
```text
Exception: java.lang.OutOfMemoryError thrown from the UncaughtExceptionHandler in thread "AsyncAppender-Worker-async-file-appender"
Exception in thread "pool-5-thread-1" java.lang.OutOfMemoryError: Java heap space
Exception in thread "AsyncAppender-Worker-async-file-appender" java.lang.OutOfMemoryError: Java heap space
Exception in thread "dw-46" java.lang.OutOfMemoryError: Java heap space
Exception in thread "AsyncAppender-Worker-async-console-appender" java.lang.OutOfMemoryError: Java heap space

```
> This is due to the `default JVM Heap Space configuration (1 GiB)` being not enough for your workloads. In order to 
> resolve this issue, head over to your openmetadata environment variables list and append the below environment variable

```shell
# environment variable file (either .bash_profile or .bashrc or add in conf/openmetadata-env.sh in release binaries)
export OPENMETADATA_HEAP_OPTS="-Xmx2G -Xms2G"
```
