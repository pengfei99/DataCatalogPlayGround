# Install and configure open metadata



## 1. Download the distribution

You can get the latest release from the GitHub repo: https://github.com/open-metadata/OpenMetadata/releases/latest

At the time(02/12/25), the latest release is 1.9.x. So we run the below command to get the tar ball

```shell
wget https://github.com/open-metadata/OpenMetadata/releases/download/1.10.11-release/openmetadata-1.10.11.tar.gz

mkdir -p /opt/openmeta
mv openmetadata-1.10.11.tar.gz /opt/openmeta/

# untar it
tar -xzvf openmetadata-1.10.11.tar.gz

cd openmetadata-1.10.11

```

> All the **OM conf files** is located at the `conf` folder
> 
> 


## 2. Create a service account for openmetadata

```shell
# create group
sudo groupadd openmeta

# create service account
sudo useradd  -g openmeta -d /opt/openmeta openmeta

sudo chown -R openmeta:openmeta /opt/openmeta

sudo chmod -R 750 /opt/openmeta

sudo mkdir -p /var/log/openmetadata
sudo chown -R openmeta:openmeta /var/log/openmetadata
sudo chmod -R 750 /var/log/openmetadata
```



## 2. Configure the openmeta app

The main configuration file of OM is found under `path/to/openmetadata/conf/openmetadata.yaml` 

We don't change the default config, but we overwrite them with env vars


Below is the complete version of the `openmetadata-env.sh`.

```shell
#!/bin/bash
###################### conf for java ##########################
JAVA_HOME="/opt/java/jdk-21.0.2"
###################### conf for db ##############################
DB_DRIVER_CLASS="org.postgresql.Driver"
DB_SCHEME="postgresql"
# this line config the jdbc connection parameters that disable SSL, allow key retrieval, and set the timezone.
# this parameters are valid for mysql not for postgres. postgres will just ignore them
DB_PARAMS="allowPublicKeyRetrieval=true&useSSL=true&serverTimezone=UTC"
DB_USER="openmetadata_user"
DB_USER_PASSWORD="openmetadata_password"
DB_HOST="localhost"
DB_PORT="5432"
OM_DATABASE="openmetadata_db"
################ conf for el #####################################
ELASTICSEARCH_SOCKET_TIMEOUT_SECS='60'
SEARCH_TYPE="elasticsearch"
ELASTICSEARCH_HOST="localhost"
ELASTICSEARCH_PORT="9200"
ELASTICSEARCH_SCHEME="http"
ELASTICSEARCH_USER="elastic"
ELASTICSEARCH_PASSWORD="elastic_password"

################# conf for authentication ########################
AUTHENTICATION_PROVIDER="basic"
# This flag indicates if users can come and signup by themselves on the OM
AUTHENTICATION_ENABLE_SELF_SIGNUP="true"

################## conf for authorizer #######################
AUTHORIZER_ALLOWED_REGISTRATION_DOMAIN='["casd.eu"]'
AUTHORIZER_PRINCIPAL_DOMAIN="casd.eu"
AUTHORIZER_ENFORCE_PRINCIPAL_DOMAIN="false"
AUTHORIZER_ENABLE_SECURE_SOCKET="false"
AUTHORIZER_USE_ROLES_FROM_PROVIDER="false"
################### conf for jwt ############################
JWT_ISSUER="casd.local"
JWT_KEY_ID="casd-self-gen-2025-12-02"
```

> Add this file to `/opt/openmeta/openmetadata-1.10.11/conf`
> 
> Don't forget to check the java path and passwords 




## 3. Init the databases and indexes

The command below will generate all the necessary tables and indexes in ElasticSearch.

```shell
# go to the root dir of openmeta
cd /opt/openmeta/openmetadata-1.10.11/

# login as openmeta
sudo su -l openmeta
# load the env var
set -a
source conf/openmetadata-env.sh
set +a

# check the db config
export -p | grep DB_

./bootstrap/openmetadata-ops.sh drop-create
```
> Before running this command, make sure you have the required config setup in the `openmetadata.yaml`(e.g. login, pwd for elastic and postgresql/mysql).
> Otherwise, you will receive many error messages.

## 4. Start/stop the openmetadata service

After the `database tables` and `elasticsearch index` are created, you can now run the `openmetadata service`.

```shell
# start the om service
./bin/openmetadata.sh start

# the above command will start the om web server at port 8585
curl http://localhost:8585 
# and the web service at port 8586
curl http://localhost:8586

# get the status of om service
./bin/openmetadata.sh status
# expected output
OpenMetadata running with PID=142200.


# stop the om service
./bin/openmetadata.sh stop
```

> We recommend configuring serviced to monitor the OpenMetadata command to restart in case of any failures.
> 

## 5. Enable JWT tokens

Once a user logs in with username/password, the service issues a JWT token for that session. 
That token is signed with the `private key (rsaprivateKeyFilePath)` and validated on every request with the
`public key (rsapublicKeyFilePath)`.

OM comes with a default private/public key pair and configuration, for test purpose, you can use them.

```yaml
jwtTokenConfiguration:
  rsapublicKeyFilePath: ${RSA_PUBLIC_KEY_FILE_PATH:-"/opt/openmetadata/conf/public_key.der"}
  rsaprivateKeyFilePath: ${RSA_PRIVATE_KEY_FILE_PATH:-"/opt/openmetadata/conf/private_key.der"}
  jwtissuer: ${JWT_ISSUER:-"open-metadata.org"}
  keyId: ${JWT_KEY_ID:-"Gb389a-9f76-gdjs-a92j-0242bk94356"}
```

For **production deployment**, it is a MUST to `update the JWT configuration`. 

To create private/public key use the following commands can be used:

```shell
# generate a rsa private key
openssl genrsa -out private_key.pem 2048
# convert private key to .der
openssl pkcs8 -topk8 -inform PEM -outform DER -in private_key.pem -out private_key.der -nocrypt
# gen public key in .der
openssl rsa -in private_key.pem -pubout -outform DER -out public_key.der
```

> Copy the `private_key.der` and `public_key.der` in OpenMetadata server conf directory. 
> Make sure the permissions can only be readable by the user who is starting OpenMetadata server.

Below are the modification you need in `openmetadata.yaml`

```yaml
jwtTokenConfiguration:
  rsapublicKeyFilePath: "/opt/openmetadata/conf/public_key.der"
  rsaprivateKeyFilePath: "/opt/openmetadata/conf/private_key.der"
  # Identifier for who issued the token.
  # Clients and services may check this value to ensure tokens come from the right source.
  jwtissuer: "casd.local"
  # A unique identifier for the signing key. Useful if you rotate keys (so multiple public keys can exist in JWKS).
  keyId: "casd-self-gen-2025-09-02"

```

below lines are set up for `openmetadata-env.sh` to avoid editing `openmetadata.yaml` directly.

```shell
export JWT_ISSUER="casd.local"
export JWT_KEY_ID="casd-self-gen-2025-09-02"
```


## 6. Create systemd unit file for OM

Below is an example of systemd unit file for OM. For more details of systemd, you can visit this [page](https://github.com/pengfei99/LinuxAdminSys/blob/main/docs/debian_server/core/Systemd(serviced).md)

```shell
[Unit]
Description=OpenMetadata Service
After=network.target
Wants=network.target
Requires=postgresql.service elasticsearch.service

[Service]
Type=forking
# Run as non-root user
User=openmeta
Group=openmeta
WorkingDirectory=/opt/

# load env var
EnvironmentFile=-/opt/openmetadata/conf/openmetadata-env.sh

# How to start and stop
ExecStart=/opt/openmetadata/openmetadata.sh start
ExecStop=/opt/openmetadata/openmetadata.sh stop

# checking service health.
ExecReload=/opt/openmetadata/openmetadata.sh status
# Optional: status and clean hooks
ExecStartPre=/opt/openmetadata/openmetadata.sh clean

# Restart policy if the service crashes
Restart=on-failure
RestartSec=5

# Logging: send stdout/stderr to systemd journal
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target

```


## 6. Java Memory Heap Issue

If your openmetadata application logs speak about the below issue -
```text
Exception: java.lang.OutOfMemoryError thrown from the UncaughtExceptionHandler in thread "AsyncAppender-Worker-async-file-appender"
Exception in thread "pool-5-thread-1" java.lang.OutOfMemoryError: Java heap space
Exception in thread "AsyncAppender-Worker-async-file-appender" java.lang.OutOfMemoryError: Java heap space
Exception in thread "dw-46" java.lang.OutOfMemoryError: Java heap space
Exception in thread "AsyncAppender-Worker-async-console-appender" java.lang.OutOfMemoryError: Java heap space

```
> This is due to the `default JVM Heap Space configuration (1 GiB)` being not enough for your workloads. In order to 
> resolve this issue, head over to your openmetadata environment variables list and append the below environment variable

```shell
# environment variable file (either .bash_profile or .bashrc or add in conf/openmetadata-env.sh in release binaries)
export OPENMETADATA_HEAP_OPTS="-Xmx2G -Xms2G"
```
